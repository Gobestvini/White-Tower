# Полная реализация White Tower по GDD

Очередь из 34 самостоятельных заданий доводит пустой каркас до проверенной production сборки браузерной игры из 120 уровней. Созданы задания, а не игровая реализация. [INDEX](INDEX.md) содержит статусы и зависимости; готова TASK-0001. Остальные draft, поскольку их зависимости ещё не выполнены.

## Проверенная исходная точка

2026-10-08, Git `71d9f41bfe9dfbea925d325499d369bfb2c13065`; Canvas 2D, JS/Vite 7.1.9, createScene только считает время/заливает фон. RAF/resize/pause/reset/visibility в main, fixed step 1/60 с max 8, keyboard/blur в input. TypeScript, WebGL, контент и saves отсутствуют. Локально присутствует каркас, но Git пока отслеживает только материалы знаний/навигацию. [Хэши проверенных входов](baseline.json) различают tracked/local файлы. Сначала TASK-0001 делает основу воспроизводимой; текущая подготовка не включает существующий каркас в свой коммит.

Главный источник: [GDD 1.0](../knowledge/white-tower/White_Tower_GDD.md), [видео](../knowledge/white-tower/source-video.mp4), [12 кадров](../knowledge/white-tower/README.md). GDD прочитан целиком при подготовке. Его наблюдения, предложенные правила и бюджеты имеют разные статусы. Пути/API будущих модулей — предложения автора заданий, а не найденная реализация.

## Порядок выполнения

Зависимости INDEX задают допустимый порядок, номер — удобный последовательный маршрут. Независимость некоторых задач не разрешает одновременные изменения одних файлов. Основные общие точки: main/scene, package/verify, renderer/projection, UI/style и content catalog. Автор очереди не запускает агентов или новые чаты.

Первый шаг: [TASK-0001](TASK-0001-project-foundation.md). После каждой задачи проверить done/отчёт зависимостей, перечитать только нужный код и обновить контекст следующей. Ошибки обнаруженной реализации оформлять отдельными ограниченными исправлениями, не скрывать их под задачей «полировать всё».

Визуальный gate TASK-0013 принят владельцем 2026-10-09. TASK-0019 добавила оригинальный уровень 12 и проверила его вместе с 11 реконструкциями. Владелец распорядился выполнить всю очередь без промежуточных ревью и посмотреть результат в конце; реальные устройства и ручные playthrough отмечаются отдельно и не подменяются эмуляцией. TASK-0020 открывает производство оставшихся 108 уровней; для авторского контента шесть тематических блоков сохраняются, первые 11 сцен видео не изменяются ради общего размерного/обучающего шаблона.

## Решения и границы

- Нормативные правила разделов 6–7 применяются до сверки видео в 0007/0013. При противоречии корректируются явно и перепроверяются все решения; правила не выбирает отдельно каждый исполнитель.
- Runtime логика — TypeScript без DOM/renderer. Лёгкий WebGL выбирается исследованием 0002; 2D — запасной режим с общей проекцией. Физика не требуется.
- Полный объём здесь: 120 уровней, бесплатные Undo/Restart/Hint, EN/RU, settings, sound effects, доступность, локальный progress, экспорт/импорт, офлайн после кэширования, editor и проверка релиза.
- Музыка, vibration, сетевой analytics SDK, account/cloud sync, реклама/покупки, TV/консоли и невыбранные встроенные площадки не обязательны по GDD. Сроки 33–51 день из GDD не принимаются за обещание этой очереди.
- Подготовка release candidate не публикует сайт. Публикация и запуск Telegram требуют отдельного запроса. Commit/push разрешены существующими инструкциями проекта.
- Недоступный телефон, Safari, предыдущая версия, RAM измерение или участник не превращаются в пройденную проверку. Исполнитель пишет конкретный пробел и оставляет review/blocked до решения; автоматические проверки этого не заменяют.

## Проверка подготовки очереди

9 октября 2026 года владелец поручил пройти все задачи без промежуточного ревью. Реализация добавила 120 уровней, редактор, проверку контента, перенос сохранений, PWA и восстановление renderer. `pnpm check:full`, campaign browser scenario, error-retry scenario, PWA offline preview и WebGL context-loss scenario прошли в записанных окружениях.

TASK-0021–0034 остаются `review`, где обязательные человеческие проверки (проходимость и читаемость всех уровней, физические устройства, длительная сессия и игроки) недоступны без владельца/внешних участников. Они записаны как ожидающая финальная приёмка; viewport эмуляцию и solver не выдаём за выполненное ручное тестирование. Релиз собран локально, публикация не выполнялась.
