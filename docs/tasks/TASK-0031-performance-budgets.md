## 4. Требуемое поведение

- Зафиксировать модели: Android среднего класса возрастом 3–4 года, доступный iPhone, Windows ноутбук со встроенной графикой, iPad; OS/browser/режим/DPR/прогрев/сценарий. Недоступное устройство остаётся непроверенным критерием.
- Цели GDD: 60FPS нормальный режим, стабильные 30FPS облегчённый, первый видимый отклик≤100 мс, обычная симуляция<5 мс, Hint обычно≤300 мс и максимум 2 с. Собирать frame times/p95 и длинные маршруты, не среднее только статичного экрана.
- Cold load≤3 с при 10 Мбит/с RTT100 мс — три прогона; начальная сжатая передача≤3 МБ, вся кампания≤12 МБ без QA. Проверить реальные Network/bundle данные, исключение референсов/editor и lazy audio.
- Память цель≤150 МБ с честной методикой/ограничениями iOS; 15 мин нагрев/батарея и повторные переходы. Отделить JS heap, GPU счётчики и недоступные измерения.
- Оптимизировать только измеренный узкий участок: shared geometry, DPR, тени, stationary redraw, Worker. Adaptive quality снижает сначала тени/DPR, потом 30FPS; палитра/толщина/стрелки/логика остаются прежними. При shared visual изменениях повторить принятие эталонов.
