## 4. Требуемое поведение

- У клетки целые u/v, kind normal/redirect/blocked и валидное направление при redirect; у стопки целые u/v, height≥1 и необязательное launchDirection. Векторы SE(1, 0), SW(0, 1), NW(−1, 0), NE(0,−1), E(1,−1), W(−1, 1), N(−1,−1), S(1, 1).
- Поддержать schemaVersion, id, title, cells, stacks, totalTiles, cameraPreset, tutorialKey, parMoves, knownSolution. Валидатор проверяет уникальность координат, пол под стопками, сумму высот, направления, стартовую победу, неизвестную версию и числовые пределы; никаких исполняемых данных.
- validateLevel возвращает discriminated result с ошибками, createInitialState создаёт независимый снимок. Данные координат не зависят от DOM/renderer; изменение полученного снимка не меняет источник.
- Проверка knownSolution здесь структурная; доказательство решения подключается после TASK-0004/0006. Явно документировать эту границу, не объявлять уровень решаемым только после parse.
- Добавить deriveCounter и isWon: X=0 при максимальной высоте<2, иначе максимум; N — сумма стартовых высот. Для победы нужна ровно одна стопка высоты N. Для циклов/решателя подготовить канонический stateKey по координатам, высотам и стрелкам, независимый от порядка массивов.
