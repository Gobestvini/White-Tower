## 4. Требуемое поведение

- createGameController владеет LevelState и историей. loadLevel, launch, undo, restart, finishAnimation, snapshot и dispose — единые точки мутации. Scene остаётся адаптером; не дублировать модель в UI.
- Разделить committedState (устойчивый итог для сохранения) и displayedState (для будущей анимации). Запуск из Idle рассчитывает весь ход, атомарно записывает прежний снимок и итог, затем переводит в Animating. finishAnimation публикует Idle/Won.
- Покрыть Loading, Idle, Animating, Won, Menu, LoadError, Unsupported. Переходы меню разрешены только из устойчивых состояний, закрытие возвращает прежнее. Результаты старых generation/request IDs не изменяют новый уровень.
- В Animating другие launch/Undo/Restart отклоняются и не ставятся в очередь. Многократные завершения и двойные клики не публикуют ход повторно. Rejected маршрут не попадает в историю.
- Undo восстанавливает все стопки/стрелки и счётчик одним действием на полный маршрут; отмена Won скрывает победу, но не удаляет отметку прохождения. Restart очищает текущую историю и attemptId, сохраняет коллекцию; новая загрузка также создаёт отдельную попытку.
