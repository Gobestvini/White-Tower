## 4. Требуемое поведение

- createStore использует IndexedDB→localStorage→память, ловит quota/security/denied ошибки. Игра остаётся доступна; store сообщает UI memory-only режим, не блокирует ход бесконечной записью.
- Save содержит schemaVersion, contentVersion, level checksum, unlockedLevel, completedLevels, selectedLevel, settings, текущий committedState и до 50 предшествующих ходов. В runtime история сохраняет всю попытку; лимит 50 касается записи/reload.
- При launch атомарно публикуются итог и Undo, затем сохраняется устойчивый итог до визуального finish. При reload во время движения восстановить итог, не середину шага; N и стрелки валидировать при чтении.
- Победу и открытие следующего уровня записать одной подтверждённой операцией до разрешения Next. Повтор completion/Next не увеличивает прогресс. Undo победы не удаляет completedLevel.
- Невалидное/неизвестное сохранение не ломает приложение: сохранить объяснимое восстановление или начать попытку заново, не silently erase общий прогресс. Базовые миграции описать; импорт/экспорт, конфликт вкладок и полный content upgrade — TASK-0028.
