# Campaign content report

Catalog 1.1.0 contains 120 sequential JSON levels. All files pass schema, SHA-256, known-solution replay, bounded shortest-search and cycle checks. The 108 new levels remain candidate content until a human plays each level and confirms readability, difficulty, hint latency and touch targets. Automated replay is not a player test.

The candidate blocks exercise these shapes: 13–18 merging paths, 19–40 L-shaped redirect routes, 41–60 intersecting approaches, 61–80 empty traversal cells, 81–100 stacked merge order, and 101–120 combinations of branch layouts and heights. These are a campaign scaffold with repeated route families; they need a human design pass to verify that each theme teaches a distinct idea and is not repetitive.

## Measurement limitations

- `parMoves` is the shortest path returned by bounded solver search; this does not establish human difficulty.
- `pnpm test:performance` used Chromium with CDP 10 Mbps down / 100 ms RTT simulation: three production preview loads were 415–434 ms and transferred 161,741 bytes of resources each. Hint UI returned in 26 ms in that desktop run. This is a desktop simulation, not a physical device measurement.
- Serialized campaign JSON totals 124,560 bytes; the catalog is 19,632 bytes. Human completion time, wrong branches, actual hit areas, screen reader comprehension and device results remain **not tested**.
- Review each provisional design on desktop and a real phone; replace repetitive layouts and record route times and confusing branches here before release.
